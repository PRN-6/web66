  # 1. PRODUCT VISION

  Web68 should allow developers to analyze an existing codebase by:

  - Selecting a local project folder.
  - Dragging and dropping supported source files.
  - Providing a public GitHub repository URL.
  - Running a command-line interface.
  - Installing a VS Code extension in a future integration.
  - Importing a previously generated Web68 graph file.

  After analysis, Web68 generates an interactive, explorable network visualization of the actual source code.

  Files, directories, classes, functions, interfaces, and modules can appear as nodes. Imports, calls, inheritance, exports, and other relationships appear as edges when they can be established reliably.

  Users should be able to click a node, inspect its source, discover what depends on it, trace dependency paths, and understand the overall architecture.

  The product should combine:
  1. A reusable analysis engine.
  2. A language-adapter system.
  3. An interactive visualization application.
  4. A CLI and reusable developer package.
  5. An extensible architecture for a VS Code extension.

Web68 Implementation Plan

Context

Web68 is a Universal Codebase Intelligence & Interactive Dependency Mapping Platform. The goriented ecosystem that allows developers to analyze software projects and visualize theirarchitectural relationships (files, modules, functions, classes) through an interactive network graph.

The system must be language-agnostic, using a universal graph schema and language adapters to support multiple languages (initially JS/TS and Python). It includes a core analysis engine, a visualization frontend, a
CLI, and an SDK.

Proposed Approach

Phase 1: Foundation & Monorepo Setup

- Initialize pnpm workspace.
- Define the Universal Graph Schema (Nodes: Repository, Directory, File, Module, Class, Function, etc.; Edges: CONTAINS, IMPORTS, CALLS, etc.).
- Implement the core package for graph management and the parser-engine interface.
- Set up the file discovery system with ignore pattern support.
- Establish the testing infrastructure using Vitest.

Phase 2: Language Adapters (Vertical Slice)

- Implement the TypeScript/JavaScript adapter:
  - Integration with Tree-sitter or similar AST parser.
  - Real import resolution (relative paths, index files, aliases).
  - Symbol extraction (classes, functions).
- Implement the Python adapter:
  - Basic symbol and import extraction.
- Validate analysis output against fixture repositories.

Phase 3: Interactive Visualization (Web App)

- Build the frontend using React, Vite, and Tailwind CSS.
- Integrate React Flow or Cytoscape.js for the network graph.
- Implement the Node Inspector panel for detailed symbol/file information.
- Add basic graph interactions (zoom, pan, search, node selection).

Phase 4: Advanced Graph Features & Insights

- Implement layout engines (force-directed, hierarchical).
- Add filtering (by language, node type, relationship).
- Develop Architecture Insights:
  - Circular dependency detection.
  - Most depended-on files (bottlenecks).
  - Dependency depth analysis.
- Implement graph export/import as JSON.

Phase 5: Tooling & Ecosystem

- Develop the CLI package (web68 analyze .).
- Create the Public SDK for programmatic access to the analysis engine.
- (Optional/Later) Scaffold the VS Code extension.

Critical Files & Packages

- packages/core: Graph schema and orchestrator.
- packages/parser-engine: Adapter interfaces.
- packages/language-typescript: TS/JS specific logic.
- packages/language-python: Python specific logic.
- apps/web: The visualization frontend.
- packages/cli: Command line interface.

Verification Plan

- Unit Tests: Test individual adapters against specific code snippets.
- Integration Tests: Run analysis on fixture repositories (Python/TS samples) and verify the resulting graph edges.
- E2E Tests: Use Playwright to verify that the web app correctly renders the analyzed graph
- CLI Verification: Ensure web68 analyze produces the expected JSON output.
